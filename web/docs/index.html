Operator notes

Scan OCI images for secrets without a daemon.

layerleak reads manifests, image config, build history, and decompressed filesystem layers directly from a registry or from a local OCI layout or docker save archive. It is read-only, verifies every blob against its OCI digest, reports incomplete coverage instead of hiding it, and keeps actionable findings separate from likely test fixtures and placeholders. Values are always redacted in its output.

Quickstart

Download a release archive

Every release attaches prebuilt CLI archives, so no Go toolchain is needed: layerleak_<version>_<os>_<arch>.tar.gz for linux and darwin on amd64 and arm64, and layerleak_<version>_windows_amd64.zip. The layerleak_<version>_checksums.txt file is signed keylessly by the release workflow and every archive carries a build-provenance attestation. Verify before you run: 

version=v3.0.0
archive="layerleak_${version}_linux_amd64.tar.gz"
checksums="layerleak_${version}_checksums.txt"
base="https://github.com/brumbelow/layerleak/releases/download/${version}"
curl --fail --location --proto '=https' --tlsv1.2 --remote-name-all \
  "${base}/${archive}" "${base}/${checksums}" "${base}/${checksums}.sigstore.json"

sha256sum --check --ignore-missing "${checksums}"
cosign verify-blob \
  --bundle "${checksums}.sigstore.json" \
  --certificate-identity 'https://github.com/Brumbelow/layerleak/.github/workflows/container-release.yml@refs/heads/main' \
  --certificate-oidc-issuer 'https://token.actions.githubusercontent.com' \
  "${checksums}"
gh attestation verify "${archive}" --repo Brumbelow/layerleak \
  --signer-workflow Brumbelow/layerleak/.github/workflows/container-release.yml \
  --source-ref refs/heads/main --deny-self-hosted-runners

tar -xzf "${archive}" layerleak
./layerleak version

layerleak version prints the version, commit, build time, Go version, and platform (--format json for the same as JSON); layerleak --version prints the first line only.

GitHub Action

The repository root is a composite action that downloads the archive for the runner, verifies its checksum, the checksums file's cosign bundle, and the archive attestation, then runs layerleak scan with --no-artifacts. Pin it to a release tag; the matching archive is downloaded from that release. 

name: Image secrets
on: { push: { branches: [main] } }
permissions: { contents: read, security-events: write }
jobs:
  layerleak:
    runs-on: ubuntu-24.04
    steps:
      - id: scan
        uses: brumbelow/layerleak@v3.0.0
        with: { image: "ghcr.io/${{ github.repository }}:${{ github.sha }}", fail-on: none }
      - uses: github/codeql-action/upload-sarif@b96794f015dfd88f77b49b1c93e0fa7110f94c63 # v4.38.0
        if: ${{ always() && steps.scan.outputs.sarif-file != '' }}
        with: { sarif_file: "${{ steps.scan.outputs.sarif-file }}" }

Inputs are image (required), version, format (default sarif), fail-on (default low), allow-partial, platform, output-file, and extra-args; outputs are exit-code, result-file, sarif-file, and version. The step fails exactly when the CLI exits non-zero. See the README action reference for every input.

Go install or source build

go install github.com/brumbelow/layerleak/v3@latest
layerleak version
layerleak scan library/nginx:1.29 --format json
git clone https://github.com/brumbelow/layerleak.git
cd layerleak
go build -o layerleak .
./layerleak scan alpine:3.20 --platform linux/amd64

Building needs Go 1.27.1 or newer, and GOBIN or GOPATH/bin must be on PATH after go install. Pin a release with @v3.0.0 instead of @latest. The module path is github.com/brumbelow/layerleak/v3; the root path without /v3 stays at v1.0.0 forever, so always include the suffix. The binary is still named layerleak. Module-installed binaries report the resolved module version; checkout builds report a VCS-derived development version, or dev without VCS information. The CLI runs on Linux, macOS, and Windows on amd64 and arm64; the API image supports linux/amd64 and linux/arm64.

02

Scan model

layerleak resolves images on Docker Hub, GHCR, Quay, GCR, MCR, Amazon ECR Public, and other OCI-compatible registries, and reads local image layouts and archives. It does not need a Docker daemon and does not check whether a detected credential is live.

Single image

A bare repository scans its latest tag. Use a tag or digest for an immutable target.

layerleak scan ubuntu
layerleak scan alpine@sha256:<digest>
layerleak scan ghcr.io/homebrew/core/hello:latest

Repository sweep

--all-tags explicitly enumerates the public tags of a bare repository, resolves each to a digest, and scans each distinct digest once.

layerleak scan mongo --all-tags \
  --max-repository-tags 500 \
  --max-repository-targets 200

Local image

Images that were never pushed are read from the filesystem. The CLI only: the HTTP API rejects these references.

layerleak scan oci:./build/image:1.2
layerleak scan oci-archive:app.tar:app:1.2
layerleak scan docker-archive:save.tar:app:1.2

Private registry

The password or token is read from standard input; there is no --password flag.

printf '%s' "$REGISTRY_TOKEN" | layerleak scan \
  ghcr.io/org/private-app:1.2 \
  --username robot --password-stdin

Platforms

Without --platform, every linux manifest of a multi-platform index (and every manifest that names no operating system) is scanned. Manifests for other operating systems are not downloaded and are reported as platform_skipped diagnostics. Index entries that are not image manifests are never scanned and are reported as manifest_skipped: BuildKit attestation manifests (annotated vnd.docker.reference.type: attestation-manifest), manifests that declare an artifactType such as application/vnd.in-toto+json, unknown/unknown platform entries, nested indexes, and descriptors of any other media type. Skipped entries do not fail the scan.

--platform os[/arch[/variant]] selects platforms explicitly; omitted parts match anything and variants are normalised like containerd, so --platform linux selects every Linux manifest and linux/arm64/v8 equals linux/arm64. With a selector, non-matching entries are left out without a diagnostic, and a single-manifest image whose config does not match fails with platform_not_found. A selected manifest whose layers are foreign or non-distributable (Windows base layers) or use an unknown media type is reported as manifest_unsupported: that platform fails, the others still run, and the result is partial.

Local inputs

ReferenceSource
oci:<dir>[:<tag>][@<digest>]An OCI image layout directory (oci-layout, index.json, blobs/), as written by buildx --output type=oci, skopeo copy ... oci:, or crane pull --format oci.
oci-archive:<file.tar>[:<tag>][@<digest>]The same layout inside a tar archive (buildx --output type=oci,dest=..., skopeo copy ... oci-archive:).
docker-archive:<file.tar>[:<repo>[:<tag>]][@<digest>]A docker save archive (manifest.json, config and layer tars, optional repositories).

The path is absolute or relative to the working directory and ends at the first colon (a Windows drive letter stays in the path). The tag is the org.opencontainers.image.ref.name annotation (for oci: and oci-archive:) or the docker save RepoTags name, and an image name matches in any spelling that normalises to it. A source holding several images needs a tag or @<digest>; --all-tags enumerates the tags the source holds. The source string becomes the repository (oci:/srv/images/app) and the stored registry is local. Every blob is verified against its descriptor digest and size, archives are indexed in memory and never extracted, links inside archives are never followed, and registry credentials are refused for a local source (exit 1).

Private registries and egress

--username <name> --password-stdin supplies a credential for one scan; both flags are required together and exactly one trailing newline is removed from standard input. Without the flags, the CLI applies the LAYERLEAK_REGISTRY_USERNAME/LAYERLEAK_REGISTRY_PASSWORD pair to the registry of the reference on the command line. The API applies that pair only when LAYERLEAK_REGISTRY_BASE_URL pins the registry endpoint, so a caller can never make the server send the operator's credential to a registry the caller names. LAYERLEAK_DOCKER_CONFIG names a Docker config.json whose auths entries supply credentials by registry host in both; credential helpers are not invoked and ~/.docker/config.json is never read implicitly. A credential is bound to the one registry host it was given for, is sent only over https, and never appears in logs, output, scan records, or the database. A 401 or 403 exits 1 with authentication to <registry host> failed.

HTTPS_PROXY, HTTP_PROXY, and NO_PROXY are honoured. When a proxy is selected for a request, the registry hostname is sent as the CONNECT target and local DNS resolution and IP pinning are skipped, because the proxy is the egress control; the https-only rule and the private-host allowlists still apply. Hosts matched by NO_PROXY are connected directly with address pinning. LAYERLEAK_REGISTRY_BASE_URL is not a proxy setting: it replaces the registry endpoint for every scan (a pull-through mirror or an alternate registry). Private, loopback, link-local, and other non-public destinations are blocked unless their exact host[:port] is listed in LAYERLEAK_ALLOWED_PRIVATE_REGISTRY_HOSTS or LAYERLEAK_ALLOWED_PRIVATE_AUTH_HOSTS; allowlisting a host is also what permits plain http:// to it.

What is scanned

  • Filesystem. Regular files in the final filesystem (file_final) and earlier versions of files that a later layer deleted or overwrote (file_deleted_layer), reconstructed layer by layer with whiteouts. Files with a UTF-16 byte-order mark or shape are transcoded to UTF-8 first. Binary files are excluded; files over LAYERLEAK_MAX_FILE_BYTES are skipped with a files_skipped_oversize diagnostic and coverage becomes partial.
  • Nested archives. A zip, jar, war, wheel, egg, gzip, or tar file inside a layer is expanded one level in memory and its entries are reported under outer/path!inner/path. An archive inside a nested archive is never opened; anything beyond a bound is a nested_archive_skipped diagnostic and coverage stays complete.
  • Image metadata. Config environment variables (env), labels (label), build history commands, comments, and authors (history), and other config fields such as the command, entrypoint, user, and working directory (config).
  • Unreadable sensitive files. A binary or oversize file whose path marks a private key, keystore, password database, credential store, or GPG keyring is reported by path alone under the sensitive_file_* identifiers, with an empty redacted_value and context_snippet and zero offsets.
  • Placeholders. Matches that look like test fixtures, examples, or placeholders (test and example paths, placeholder markers, known dummy values, example hosts, well-known default credentials) are reported as suppressed findings with disposition example and a disposition_reason, and do not count as actionable.

Detection uses a compiled, read-only catalog of 161 detector identifiers; there is no rule file or custom-rule syntax. layerleak detectors list prints each identifier with its confidence tier, matching strategy, and description (--format json for JSON), and the same data is published as the detector catalog.

Repository sweeps accept --tag-page-size, --max-repository-tags, and --max-repository-targets, which override the matching environment variables for one command. --max-repository-tags and --max-repository-targets accept 0 to disable the cap; --tag-page-size must be greater than zero.

Configuration

Every setting is an environment variable with a safe default; no process reads a .env file itself. .env.example in the repository lists them with their defaults and the README configuration tables are the reference; the tables below carry the same rows. Durations use Go syntax (30s, 10m, 1h). Booleans accept 1, true, yes, on and 0, false, no, off. Rows marked must be positive reject 0; every other MAX_* bound accepts 0 to disable it. Exceeding a scan bound never truncates silently: the scan becomes partial or failed and a diagnostic names the bound. Two bounds are informational instead: the nested-archive bounds add a nested_archive_skipped diagnostic and the raw-value bound adds a raw_retention_truncated diagnostic, and coverage stays complete for both.

04

Results

--format summary (the default) prints counts, a per-target table, and the first 50 actionable findings; --format json prints the stable result (result_schema_version 2, described by schemas/result-v2.schema.json); --format sarif prints a SARIF 2.1.0 log. --output <file> writes the formatted output to a file created with mode 0600 instead of stdout (- is stdout). Every result has a top-level status (completed, partial, or failed), a coverage object, per-target, per-platform, and per-tag status, and diagnostics. --format json prints the result for failed scans too, so automation can read the diagnostics. The silent paths are cancellation and failures before any result exists (invalid input, an unreadable local source, or an error opening the store): those print only the error on stderr and exit 1.

Exit codes

CodeMeaning
0Complete scan with no blocking findings, or an accepted (--allow-partial) usable partial scan with none.
1Invalid input, operational failure (registry, network, authentication), persistence failure, or cancellation (LAYERLEAK_SCAN_TIMEOUT, SIGINT, SIGTERM).
2One or more actionable findings at or above --fail-on. Findings take precedence over incomplete coverage.
3The scan finished with usable but incomplete coverage and --allow-partial was not given.

--fail-on low|medium|high|none sets the lowest confidence of an actionable finding that produces exit code 2: low (the default) is every actionable finding and none reports without failing. --allow-partial accepts usable incomplete coverage (exit 0 or 2 instead of 3) without hiding the missing coverage. Scripts that retry on 1 should treat 3 as "investigate coverage". A second SIGINT or SIGTERM terminates the process immediately.

One scan record per scan

Every scan that produced a result, whether completed, partial, or failed, writes exactly one scan record, <dir>/<utc-timestamp>-<reference-token>-<random>.json, unless --no-artifacts is given. <dir> is --output-dir, otherwise LAYERLEAK_FINDINGS_DIR (a relative value resolves against the working directory), otherwise ./findings under the working directory; the CLI does not look for a surrounding go.mod. The full path is printed quoted on stderr (Scan record: "…"). The record (record_schema_version 2, described by schemas/scan-record-v2.schema.json) holds the same redacted result as --format json, every finding with its source_location (actionable first, then suppressed), the persistence outcome (disabled, saved with scan_run_id, or failed with storage_unavailable), and created_at. There is no separate findings file.

A missing directory is created with mode 0700; an existing directory is never chmod-ed, a symbolic link in its place is refused, and the CLI warns once when an existing directory is readable by other users. Records are written 0600 and never overwrite an existing file. If the record cannot be written, the scan still prints its result and exits 1. --no-db ignores LAYERLEAK_DATABASE_URL for one run; a database-save failure exits 1, records storage_unavailable, and still prints the result.

Finding fields

detector_name confidence disposition disposition_reason source_type manifest_digest platform file_path layer_digest key line_number redacted_value fingerprint context_snippet match_start match_end present_in_final_image

Actionable findings are listed under findings and counted in total_findings and unique_fingerprints; suppressed ones are listed under suppressed_findings and counted in suppressed_findings_count. The scan record adds source_location to each finding. fingerprint is the SHA-256 of the raw value, stable across installs; for a path-only sensitive_file_* finding it is derived from the layer digest and path. The occurrence counters and first/last-seen times belong to the HTTP API, which aggregates stored history.

Redaction

Raw secret values and raw context snippets are never written locally: stdout, the scan record, JSON, and SARIF are always redacted, even with LAYERLEAK_PERSIST_RAW_SECRETS=1. A redacted_value under 12 characters is masked completely (********); a longer value shows its first three characters followed by the same fixed eight-character mask (ghp********), so neither the length nor the tail is disclosed, and a multi-line value becomes [REDACTED MULTILINE]. In context_snippet every copy of the matched value is replaced with [REDACTED]. Raw persistence exists only in PostgreSQL with LAYERLEAK_PERSIST_RAW_SECRETS=1, and the API and scan history stay redacted even then.

Baselines

A baseline file accepts reviewed findings by fingerprint so a rotated secret left in an old layer does not fail every run. Nothing is read implicitly; pass the file with --baseline. 

layerleak scan ghcr.io/org/app:1.2 --format json --output result.json --fail-on none
layerleak baseline create --from result.json --reason "rotated 2026-09-01; old layer only"
layerleak scan ghcr.io/org/app:1.2 --baseline layerleak-baseline.json

baseline create reads a result or a scan record and writes one entry (fingerprint, detector, reason) per actionable finding to layerleak-baseline.json with mode 0600, never overwriting without --force and never writing values, paths, or snippets. Entries may carry an RFC 3339 expires. A matched finding is reported with disposition: baselined among suppressed_findings and never produces exit code 2. This is a per-caller view applied by the CLI: stdout, the scan record, SARIF, and the exit code see it, while the database and therefore the HTTP API keep the scanner's disposition. A malformed baseline exits 1 before the scan starts.

SARIF

--format sarif writes one SARIF 2.1.0 run per scan: every default detector under tool.driver.rules, a result per finding with level from its confidence, a layerleak/fingerprint/v1 partial fingerprint, the image reference as the IMAGE URI base, and a suppressions entry on suppressed and baselined findings. Only redacted values are written. 

layerleak scan ghcr.io/org/app:1.2 --format sarif --output layerleak.sarif --fail-on none --no-artifacts
05

Postgres persistence

The API and persistent CLI mode need PostgreSQL 16.13 or newer. Migrations are explicit: the API never creates or upgrades schema, refuses to start unless the installed schema is exactly version 0004, and /readyz re-checks the database and schema afterwards. From a checkout, against a local database: 

export LAYERLEAK_DATABASE_URL='postgres://layerleak@127.0.0.1:5432/layerleak?sslmode=disable'
export PGPASSWORD='<password>'
export LAYERLEAK_MIGRATIONS_DIR="$PWD/migrations"
go run ./cmd/migrate --status
go run ./cmd/migrate

Without flags the command applies every pending migration and a rerun is a no-op. --status prints the ledger (each shipped migration with its state, applied time, and SHA-256, then current and expected) and exits 0 when the database is current, 2 when migrations are pending or a legacy schema is waiting to be adopted, and 1 on any error such as checksum drift. --dry-run lists what a run would adopt and apply and changes nothing; --version prints the build version. The command holds an advisory lock with bounded waits, records checksums in a migration ledger, runs one transaction per migration, and refuses drift, gaps, dirty state, or a partial legacy schema. There is no down command.

Current state is deduplicated by (manifest_digest, fingerprint) in findings, with one row per place a value was seen in finding_occurrences. Append-only scan history lives in scan_runs as a redacted snapshot of the public result, regardless of LAYERLEAK_PERSIST_RAW_SECRETS.

Purging raw values First set LAYERLEAK_PERSIST_RAW_SECRETS=0 on every API and CLI database writer and restart or stop them. layerleak-purge-raw-secrets --dry-run reports how many raw values and snippets would be cleared; --confirm clears only findings.value and finding_occurrences.raw_snippet in id-range batches of --batch-size rows (default 5000), one transaction per batch, and keeps redacted findings and history. Committed batches stay purged if a later one fails, so a failed run can be rerun. Raw material lingers in dead tuples until vacuum and in WAL archives, replicas, and backups taken before the purge.

06

HTTP API

The API binary (layerleak-api in the image, cmd/api in the source) is JSON-only and PostgreSQL-backed: it requires LAYERLEAK_DATABASE_URL and never reads scan records. It listens on plain HTTP; deploy it on a private network behind TLS termination and an authenticating gateway that also rate-limits.

  • GET/health
  • GET/livez
  • GET/readyz
  • POST/api/v1/scans
  • GET/api/v1/scans/{id}
  • GET/api/v1/repositories
  • GET/api/v1/repositories/{repository}/scans
  • GET/api/v1/repositories/{repository}/findings
  • GET/api/v1/findings/{id}

/health and /livez report process liveness and the build version without querying PostgreSQL. /readyz requires a database ping and schema version 0004, reuses its answer for LAYERLEAK_API_READINESS_CACHE_TTL, and answers 503 not_ready while the process drains.

POST /api/v1/scans is synchronous and accepts reference, optional platform, and optional all_tags; unknown fields are rejected. A bare reference means latest unless all_tags is true. Local sources (oci:, oci-archive:, docker-archive:) are rejected with 400 invalid_request. The response carries scan_run_id and the redacted result; unlike the CLI, its error fields read scan step failed and diagnostic messages are fixed text chosen by diagnostic code. Incomplete work returns 422 scan_incomplete or scan_limit_exceeded, and a scan that finished but could not be persisted returns 503 storage_unavailable with the result and without a scan_run_id. Scans beyond LAYERLEAK_API_MAX_CONCURRENT_SCANS get 429 scan_capacity_exceeded. 

curl --fail-with-body \
  -H 'Content-Type: application/json' \
  -H "Authorization: Bearer $API_TOKEN" \
  -d '{"reference":"alpine:3.20","platform":"linux/amd64"}' \
  http://127.0.0.1:8080/api/v1/scans

List endpoints accept limit (default 50, clamped to 200) and offset, and every list response returns next_cursor: an opaque keyset position when the page was full, or "" when the listing is exhausted. Pass it back as cursor so deep pages cost the same as the first; a cursor is tied to one endpoint and cannot be combined with a non-zero offset. Repository endpoints accept registry as host or host:port (default docker.io), the {repository} segment accepts a literal / or %2F, and the finding list accepts disposition=actionable|suppressed|all (default actionable).

Stored finding fields

id manifest_digest fingerprint redacted_value detectors occurrence_count actionable_occurrence_count suppressed_occurrence_count first_seen_at last_seen_at

GET /api/v1/findings/{id} adds the redacted occurrences history. These aggregates come from the database and are not part of the CLI result.

Bearer tokens are opt-in Authentication is off by default. Setting LAYERLEAK_API_BEARER_TOKENS (comma-separated) or LAYERLEAK_API_BEARER_TOKENS_FILE (one per line) requires Authorization: Bearer <token> on every /api/ path; a missing or unknown token answers 401 unauthorized with WWW-Authenticate. /health, /livez, and /readyz stay open. Tokens are at least 32 characters, held only as SHA-256 digests, compared in constant time, and never logged, and the API warns at startup when it listens on a non-loopback address without tokens. This is defence in depth, not authorization: there are no users, roles, or tenants, so keep TLS termination and your gateway.

LAYERLEAK_API_METRICS_ADDR adds a second listener that serves Prometheus text-format metrics at GET /metrics: requests by route pattern and status class, request durations, scans by outcome and error code, in-flight scans, process start time, and build info. Labels never carry paths, references, or request bodies. It must differ from LAYERLEAK_API_ADDR and is unauthenticated, so bind it to a private interface. The API logs one record per request (JSON by default, key=value with LAYERLEAK_LOG_FORMAT=text; method, route pattern, status, bytes, duration, request id, remote address) and never the path, query, or body.

On SIGTERM or SIGINT the API drains: for LAYERLEAK_API_PRESTOP_DELAY /readyz answers 503 and new scans are refused with 503 server_shutting_down while in-flight requests continue; then in-flight scans are cancelled with 503 server_shutting_down and the server stops within LAYERLEAK_API_SHUTDOWN_TIMEOUT, exiting 0.

Container & Compose

The published image supports linux/amd64 and linux/arm64. It is shell-free, runs as UID/GID 10001, works with a read-only root filesystem, and contains CA roots, the migrations, and four static binaries: layerleak-api (the default entrypoint, listening on 0.0.0.0:8080), layerleak-migrate-up, layerleak-purge-raw-secrets, and layerleak-healthcheck, which probes /readyz with a two-second deadline. It does not contain the layerleak CLI. Pin it by release tag or, better, by the image.index_digest in the release's release-manifest.json (ghcr.io/brumbelow/layerleak@sha256:<digest>) instead of :latest. 

docker pull ghcr.io/brumbelow/layerleak:v3.0.0
docker run --rm \
  -p 8080:8080 \
  -v /path/to/postgres-ca.pem:/etc/layerleak/postgres-ca.pem:ro \
  -e LAYERLEAK_DATABASE_URL='postgres://<user>:<password>@<host>:5432/layerleak?sslmode=verify-full&sslrootcert=/etc/layerleak/postgres-ca.pem' \
  --read-only --tmpfs /tmp:mode=1777 \
  --cap-drop ALL --security-opt no-new-privileges \
  ghcr.io/brumbelow/layerleak:v3.0.0

Keep sslmode=verify-full with the mounted CA for any database that is not on the same host. Omitting sslmode is not a safe shortcut: the driver's implicit require encrypts without verifying the server certificate. Use sslmode=disable only for a database reachable solely over a private network, as the Compose file does for its db service. A password embedded in a URL must be percent-encoded; PGPASSWORD may hold any characters.

docker-compose.yml runs db (PostgreSQL 16.15 pinned by multi-platform digest), migrate, and api; purge-raw-secrets is in the tools profile. One command starts the stack: api waits for the database to be healthy and for migrate to finish, so a fresh volume becomes ready without a manual migration step. Set the required password and pin the image in .env first; the example ships the password empty and LAYERLEAK_IMAGE at :latest. 

cp .env.example .env
# In .env: set LAYERLEAK_DB_PASSWORD and pin
# LAYERLEAK_IMAGE=ghcr.io/brumbelow/layerleak:v3.0.0
docker compose config
docker compose up -d
docker compose ps
curl --fail http://127.0.0.1:8080/readyz

The API runs read-only with every capability dropped, a 256 MiB /tmp tmpfs, a 2 GiB memory limit, and a 256-process limit (mem_limit and pids_limit; mirror them under deploy.resources.limits for a Swarm stack, and raise the memory limit with any MAX_*_BYTES bound you lift). The database keeps only the five capabilities its entrypoint needs, and the one-shot migrate and purge commands run read-only on a 64 MiB tmpfs. The host port binds to 127.0.0.1 by default; change LAYERLEAK_API_HOST only when an authenticated network edge is ready. The api service has a 35-second stop_grace_period (LAYERLEAK_API_STOP_GRACE_PERIOD); whatever runs the container must allow more than LAYERLEAK_API_SHUTDOWN_TIMEOUT, otherwise an in-flight scan is killed before it is persisted. Dockge and Komodo deploy the same file. 

docker compose --profile tools run --rm purge-raw-secrets --dry-run
docker compose --profile tools run --rm purge-raw-secrets --confirm
